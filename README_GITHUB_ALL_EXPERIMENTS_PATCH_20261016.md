## Kaggle ONE-CELL use

Open `KAGGLE_GITHUB_ALL_EXPERIMENTS.py`, copy its entire contents into **one Kaggle Python notebook cell**, and run with Internet ON. It clones `https://github.com/tydeptrai21042004/pham_thi_yen.git` from the latest `main`; it does not import source from an old ZIP. It installs requirements and runs five focused preflight test modules before starting expensive experiments.

Defaults: **4 fireflies and 2 generations**, full 9-train/12-test, full 109-attack suite, 13 classical method variants, nine ablations, Y/R/G/B, security, BSS, three block sizes, reviewer statistics, sensitivity for all available hosts, extracted gallery, and an entirely separate independent second-watermark cohort (`Cc.logo.circle.png`). Runs all missing tasks when resumed or all tasks from scratch when there is no checkpoint. There are **no native TrustMark 61-bit/WAM 32-bit** calls. Neural 4096-bit extensions are **optional**: set `RUN_4096_EXTENSIONS=True` to run both TrustMark and WAM with actual full attack grid and failed decoding honestly retained. Neural requires Internet ON, large model weights, and preferably a Kaggle GPU. An optional neural run is not needed for classical completeness.

## Multi-session execution and checkpoints

A Kaggle session may not finish all of the benchmarks. The script stops within the configured session budget and writes `watermark_all_results_9train_12test.zip` in `/kaggle/working`. Download that ZIP. On a subsequent fresh Kaggle session, add it as an **Input dataset** and run the exact same cell again with no code changes. Successful per-host runs and optimizer checkpoint progress will be restored when contracts match. The nested `watermark_2_Cc.zip` is stored inside the parent result ZIP so the second cohort also resumes. Avoid connecting a checkpoint generated by a different code revision without checking the fingerprints. A checkpoint is *not* a scientific completeness certificate.

Read `/kaggle/working/watermark_all_results_9train_12test/completeness.json`: only `all_core_sections_complete: true` means the chosen requested coverage is fully validated. `expected_heldout_rows` for each watermark = **17,160**; with both watermark cohorts, 34,320 classical rows, not counting reviewer experiments. With the optional 4096-bit extensions enabled, the neural expected rows per watermark are **2,664** (including clean, control and 109 attacks). Native 61/32 bit studies are excluded from both reports and workload. Performance of 4096-bit adaptations must not be misrepresented as native payload mode.

## Scientific notes

The proposal requires side information and must be reported as **semi-blind**. The proposal's DWT-derived watermark payload and the 4096-bit neural extensions have different embedded payload semantics. Empirical BSS and security checks do not by themselves constitute mathematical or cryptographic proofs. The patch does not change embedding equations, extraction equations, objective constraints, optimizer internals, or algorithm parameters except passing the already-used four-firefly/two-generation configuration through the runner.
